# 管理员作品管理设计（角色权限 + 管理后台）

日期：2026-10-09
状态：已与用户确认（方案 A，范围仅作品），已实现（M12，见 PROGRESS.md）

## 目标

给指定账号管理员角色，可以管理**所有人**的作品：

1. 查看全量作品列表（含处理中 / 失败 / 仅自己可见 / 已下架），按状态、可见性、作者筛选。
2. 下架作品（可填原因），可恢复。
3. 删除作品。

权限在**服务端**强制校验，前端隐藏入口只是体验优化。

非目标（以后再说）：用户管理（封禁 / 禁言）、评论管理、举报体系、操作审计日志、管理员角色细分、批量操作。

## 交互设计

- 新路由 `/admin`，只有管理员能进。
- 入口放在个人主页的「⋯」抽屉里（这个抽屉本来就预留给后续功能），仅 `role=ADMIN` 时出现。
- 页面结构：
  - 顶部筛选：状态（全部 / 已发布 / 处理中 / 失败 / 已下架）、可见性（全部 / 公开 / 仅自己可见）、作者关键字（昵称或手机号）、作品 ID 精确查。
  - 列表每行：封面缩略图、ID、类型、作者、状态、可见性、发布时间、点赞 / 评论 / 播放数。
  - 操作：下架（弹原因输入）、恢复、删除（红色，二次确认）。
- 移动端同一页面自适应，列表收成紧凑卡片。
- 作者侧提示：自己作品列表里被下架的作品显示「已下架」角标（与现有私密锁角标同位置），详情里作者能看到下架原因。

## 后端设计

### 数据变更（新增 `db/init/012_m12_admin.sql`）

```sql
-- 管理员角色
ALTER TABLE `user`
    ADD COLUMN `role` VARCHAR(20) NOT NULL DEFAULT 'USER' COMMENT 'USER / ADMIN' AFTER `bio`;

-- 下架原因（管理员填写，作者可见）
ALTER TABLE `post`
    ADD COLUMN `block_reason` VARCHAR(200) NOT NULL DEFAULT '' COMMENT '管理员下架原因' AFTER `fail_reason`;
```

- `PostStatus` 增加枚举值 `BLOCKED`；`post.status` 本身就是 `VARCHAR(20)`，不需要改列定义。
- **迁移脚本里不写死管理员手机号**：仓库是公开的，不把个人手机号提交进去。提升管理员的语句放在部署文档里用占位符，本地和服务器上单独执行。

### 为什么用 status=BLOCKED 而不是新加一列

所有「只应看到正常作品」的查询本来就带了 `status = PUBLISHED` 条件（首页流、朋友流、他人主页、点赞列表、搜索等 8 处）。
新增一个枚举值，这些地方**自动**排除被下架的作品，**现有查询一行都不用改**；
如果新加一列，就得给每处查询补条件，漏一处就是漏洞。

### 接口（`/api/admin/**`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/posts` | 全量列表；参数 `status` / `visibility` / `authorKeyword` / `postId` / `cursor` / `limit` |
| GET | `/api/admin/me` | 返回 `{"admin":true/false}`，供前端判断是否显示管理入口 |
| POST | `/api/admin/posts/{id}/block` | body `{"reason":"..."}`（可选，≤200 字）；已下架则幂等返回 |
| POST | `/api/admin/posts/{id}/unblock` | 恢复为已发布 |
| DELETE | `/api/admin/posts/{id}` | 硬删，复用现有删除实现（OSS 对象 + 点赞 / 收藏 / 评论清理） |

### 权限

- `user.role`（`USER` / `ADMIN`），管理员接口统一拦截，非管理员一律 403。
- JWT 里只存了 userId，所以每次管理请求**查一次库**确认角色：管理接口流量极小，而且改了角色立即生效，不用等 token 过期。
- 「当前用户是否管理员」通过一个独立的查询接口暴露给前端（只返回布尔值），供入口显隐判断。

### 缓存与事件

- 下架 / 恢复：发 `PostUpdatedEvent`，沿用现有的首页缓存失效机制。
- 删除：走现有 `delete()`，内部已经发了 `PostDeletedEvent`。
- 下架后作者仍然看得到：`userPosts()` 在 `own=true` 时不过滤 status（见 `FeedService` 个人主页列表方法），所以个人主页照常显示，只加角标。

## 边界与决策

1. 下架可恢复、删除不可逆，所以删除必须二次确认，管理页默认主推「下架」。
2. 被下架的作品对作者可见（带角标 + 原因），避免作者以为是 bug。
3. 作者改可见性不会把作品「救回来」：下架改的是 `status`，作者只能改 `visibility`，恢复只有管理员能做。
4. 下架只对「已发布」的作品生效，对处理中 / 失败的作品返回业务错误（没有意义）；删除对任何状态都允许。
5. 管理员删除自己的作品走普通接口即可，不需要特殊分支。

## 验收标准

- 管理员登录后能看到管理入口；其他账号看不到。
- 普通账号直接请求 `/api/admin/posts` 返回 403。
- 管理列表能筛出状态为处理中 / 失败 / 仅自己可见 / 已下架的作品。
- 下架后：首页、朋友流、他人主页、点赞列表、搜索结果都不再出现；作者自己主页能看见，带「已下架」角标和原因。
- 恢复后：上述所有位置重新出现。
- 删除后：所有位置消失，OSS 对象被清理。
- 以上变化刷新页面后依然成立，不只是前端视觉消失。
