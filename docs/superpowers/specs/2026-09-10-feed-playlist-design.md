# 首页播放列表优化设计（已看沉底 + 轮换重播）

日期：2026-09-10
状态：已与用户确认，待实现

## 目标

首页信息流不再每次打开都从头播放同一批最新作品：

1. 有效观看过的作品在首页沉底，优先展示没看过的作品。
2. 全部作品都看过一遍后，按“最久没看”的顺序轮换重播，形成新的一轮。
3. 不记忆播放位置（不做续播），每次从内容的第一条开始。

## 有效观看的定义

作品停留并实际播放累计满 3 秒即记为“看过”：

- 视频：真实播放累计 3 秒（暂停、划走不计时；拖动进度条不额外计时）。
- 图文：当前屏停留累计 3 秒。
- 只在登录状态下记录；未登录用户不记录，首页保持时间倒序。
- 同一作品在一次会话内最多上报一次（上报失败的允许重试）。

## 存储设计

Redis ZSET：`feed:seen:{userId}`

- member = postId，score = 最后一次观看时间（毫秒时间戳）。
- 过期策略：记录保留 90 天；每次写入时清理 90 天前的成员并刷新 key 的 TTL。
- Redis 不可用时全部降级为“不过滤、时间倒序”，功能不报错。

## 接口

新增：`POST /api/feed/seen/{postId}`

- 需要登录（沿用 `anyRequest().authenticated()`，无需改安全配置）。
- 作品不存在时静默忽略，返回成功。
- 幂等：重复上报只更新时间。

## 首页取数算法（两段式）

`FeedService.feed(cursor, limit, viewerId)`：

### 未登录

保持现状：时间倒序 + 现有 30 秒首页缓存。

### 已登录：第一段（新内容）

1. 一次性读取该用户的已看集合（ZRANGE 全量到内存 Set）。
2. 分批从数据库按时间倒序取数据（每批 `limit * 3` 条），在应用层过滤掉已看过的，直到凑满一页或数据库取尽。
3. 未取尽或本页已满：`nextCursor` 继续使用现有时间游标格式，`hasMore = true`。
4. 数据库取尽：`nextCursor` 切换为第二阶段起始游标 `seen_0`，无缝进入轮换。

### 已登录：第二段（轮换重播）

1. 游标格式 `seen_{offset}`，按 ZSET 分数升序（最久没看在前）取一页成员 ID。
2. 用这批 ID 反查数据库，过滤掉已删除/非已发布的作品后按 ZSET 顺序输出。
3. `nextCursor = seen_{offset + 本批成员数}`；翻到末尾时回到 `seen_0` 开始新一轮。
4. 只要平台有作品，`hasMore` 恒为 true（可无限循环滑动）。
5. 用户在新一轮中的观看行为会更新 score，下一轮顺序自然变化。
6. 若某页因作品被删而过滤为空，继续顺延取下一批，最多回绕一圈，避免出现空页卡住。

### 删除的作品

第二段反查时过滤；第一段不受影响。

## 前端改动

- `api/posts.js` 新增 `markPostSeen(postId)`。
- 新增 `composables/useSeenReport.js`：
  - `createWatchTimer(postId, threshold = 3000)`：`start()` / `stop()` 控制累计计时，满 3 秒触发上报。
  - 模块级 `reported` 集合保证同一作品只上报一次，失败时移除以便重试。
- `components/mobile/FeedItem.vue`、`components/pc/PcFeedCard.vue`：
  - 视频：`onPlay` 启动计时，`onPause`/划走/卸载停止。
  - 图文：`active` 为 true 时计时（停留即算），离开当前屏停止。
  - 未登录不调用上报接口。

## 前端分页

游标对前端不透明，`nextCursor` 原样透传，`stores/feed.js` 无需结构性改动；`loadMore` 已有的按 ID 去重可覆盖轮换过程中的少量重复。

## 影响面与兼容

- `FeedService` 增加个性化分支；未登录路径不变（含缓存）。
- 个人主页、点赞列表顺序不变；在这些位置的观看同样计入“已看”，回到首页生效。
- Redis 故障：降级为时间倒序。

## 验收标准

1. 看过（满 3 秒）的作品在下次刷新首页时不再出现在新内容区，而是最后才出现。
2. 所有作品看完后，首页仍能继续滑动，按“最久没看”的顺序轮换。
3. 未登录访问首页行为与现在一致。
4. 快速划过（不足 3 秒）的作品不会被沉底，下次仍会出现。
5. Redis 不可用时首页仍可正常打开。
