# 拾光第一轮可靠性优化

日期：2026-10-16。依据用户已确认的项目检查建议实施。

## 范围与验收

1. 上传安全：服务端记录并核验上传对象归属，覆盖作品、头像、评论、私信的图片或视频入口；不压缩图片；旧内容继续可读；跨账号引用或删除不得影响他人的文件。
2. 登录续期：接通已有 refresh 接口；并发过期请求共用一次刷新；刷新调用本身不递归；刷新成功重试原请求，失败统一清理登录态并保留回跳位置。
3. 计数恢复：消除 Redis 取出增量后、MySQL 写入前的不可恢复窗口；落库重试不能重复累加；读取端正确处理待落库增量；覆盖点赞和播放量。
4. 转码补偿：任务持久化，发送失败和超时任务可恢复；有限重试、可追踪错误；并发消费者不得同时处理同一任务。
5. 集成验证：定向故障回归、现有后端测试、前端构建；按顺序提供数据库增量脚本及上线说明。

## 实施边界

- 本轮先完成可靠性；UI 精修、长列表渲染及部署监控属于后续轮次。
- 保留单体架构与现有业务行为，使用现有 Spring / MyBatis-Plus / Redis / RabbitMQ。
- 不执行生产破坏性测试，不自动提交或推送；上线前核对增量脚本与回滚边界。
- 各项先写能复现问题的测试，再补最小实现；共同配置、进度文档由主任务统一修改。

## 并行文件边界

- 上传：storage 上传归属实现、四类上传消费入口、013 增量、相关安全测试。
- 登录：前端认证和 HTTP 请求处理、登录回跳、相关回归验证。
- 计数：点赞 / 播放计数服务及恢复实现、014 增量、相关测试。
- 转码：transcode 包、015 增量、转码测试；主任务负责全局配置及整合。
